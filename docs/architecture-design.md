# 系统架构与实现边界

本文件描述当前实现。需求来源为主实施计划、源码智能增量计划与融合设计；实施前架构原文与验证完成度只保留在源码仓库中,不随发行包分发。

## 组成

前端为 Vue 3.5、Arco 与按需加载的 Monaco；八个业务路由共享目录驱动的资产表格、表单、历史、导入导出和 AI 抽屉。开发阶段由 Vite 代理后端，发行阶段前端静态产物嵌入 Spring Boot JAR，由同一端口提供页面和 REST/SSE。

浅色、暗色由统一语义颜色驱动。首屏脚本先应用浏览器选择或系统偏好，再由 `core/theme.ts` 管理系统变化、跨标签同步与生命周期。Arco 弹层通过 `body[arco-theme]` 同步，Monaco 使用独立于单个编辑器生命周期的共享监听；切换配色不改变组件、模型或资产身份。目录表单的校验模型与当前编辑草稿一致。

后端运行于 Java 21、Spring Boot 4.1.1 和 Spring AI 2.0.1。平台数据保存在 MySQL 8.4；文档、附件、源码快照与加密主密钥保存在实例的受管存储目录。没有 Kafka、Redis、MinIO 或 JMeter 运行依赖。Playwright 与 PDF 使用有上限的短生命周期子进程；它们属于单体应用的执行隔离边界。

| 代码区域 | 职责 |
| --- | --- |
| `asset` | 项目边界、资产目录、类型字段校验、CAS、排序、撤销与修订 |
| `job` | MySQL 持久队列、租约、取消、幂等及 SSE 游标 |
| `security` | 单账号平台登录、服务端会话、CSRF、API/下载保护及 SSE 会话失效检查 |
| `ai` | 公司模型适配、模板、局部反馈、全局变更集和六阶段流水线 |
| `requirement`、`api/importer`、`exchange`、`storage` | 原文抽取、接口解析、导入预检/应用、模板、便携导出与文件管理 |
| `analysis` | 固定源码、Java AST、DDL、Git Diff、影响分析和代码诊断 |
| `execution`、`engine` | 不可变运行快照、DDT、变量、HTTP/SQL/浏览器执行 |
| `report`、`bug`、`schedule`、`notification`、`workbench` | 真实报告、缺陷历史、排期、投递、质量指标与晨报 |

准确的类与路由契约见 [api-contract.md](api-contract.md)，数据库版本见 [database.md](database.md)。

## 数据与人工权威

公共资产元数据和领域表共同保存类型、项目、父级、排序、来源及业务字段；AI 和人工创建使用同一结构。子步骤是独立资产，拥有稳定 ID 和自己的修订。前端以字符串传输版本号，所有更新带 `baseVersion`，只发送改变的字段。

变更在短事务内校验项目、当前版本、字段范围和引用，再更新目标及修订。排序提交完整的同类同父范围与各项原版本，筛选列表不能用不完整集合重排。撤销也是一笔针对当前版本的新修订，不抹除历史，不覆盖后续人工编辑。已确认、保护或删除的记录不会因旧 AI 响应而自动复活或被改写。

密钥、数据库口令及敏感配置按受管主密钥加密，接口使用遮盖值。主密钥丢失无法靠重新生成密钥恢复旧密文；完整备份必须包含相同有效密钥。响应、运行证据、模型错误和便携导出进行相应脱敏。项目隔离和内容校验由后端执行，不能只依赖界面。

## 全局与局部多轮反馈

局部调优提交 `projectId`、`targetType`、`targetId`、`baseVersion`、`targetFields`、反馈、会话与幂等键。生成在数据库事务之外进行，模型只得到必要上下文。返回内容须匹配单个目标和允许字段；SQL、UI 与依赖约束通过后，才在 CAS 事务中原位替换。目标 ID、父级、顺序和未声明字段保持，兄弟资产不写入。人工先保存时，迟到候选进入冲突状态并可供查看，不覆盖人工版本。

最终局部采纳使用专用 READ COMMITTED 短事务包裹原有原子完成流程。等待项目锁后重新读取当前依赖图，能看到锁交接期间已经提交的人工消费者；任务锁、取消/租约检查、目标 CAS、修订、会话和终态同次提交。该隔离设置只作用于局部采纳，全局事务默认值保持不变。真实 MySQL 屏障回归覆盖接口提取器、SQL 结果变量和 UI 步骤导出三类并发关系。

连续反馈沿用会话并基于已采纳的当前资产，而非不断重放最初草稿。会话不能跨项目或跨目标复用；取消、断流、截断和错误响应不产生半条资产。重复提交返回同一任务/应用记录，撤销或拒绝不删除对话证据。

全局反馈先生成独立变更集，展示差异、受保护项、依赖和冲突，再由用户选择采纳。新增资产通过本地关联键映射到正式 ID；选定集合在同一事务内检查最终引用图并原子应用。只改变量生产者或只改依赖消费者等不完整选择会被拒绝。跨资产联动须经过这一流程，局部调优不会暗改其他资产来“修复”依赖。

前端抽屉保存未提交的人工草稿；AI 已采纳版本刷新显示时，不覆盖编辑器中的脏内容。刷新页面通过服务端会话、任务历史和 SSE `Last-Event-ID` 恢复。

## 五类输入与六阶段流水线

需求支持受允许目录内的绝对路径、文件上传与粘贴；Word/Excel 使用 POI，PDF 使用 PDFBox，Markdown 使用 Flexmark。接口契约经过 OpenAPI/Swagger、Postman、cURL、HAR 解析和预览；上传大小、压缩展开、格式和引用都有边界校验。

后端源码、前端源码和 DDL 导入为固定快照，记录内容哈希、路径、分析结果与未解析线索。JavaParser 提取类/方法/注解和静态调用关系；Git Diff 按旧新区间、重命名及删除定位影响面。动态派发、反射和运行时路由不被伪装为已完全解析。定向回归候选允许人工选定并生成计划。

| 阶段 | 输入、结果与缺口处理 |
| --- | --- |
| S1 | 需求降噪、规则/风险提取，并结合已选固定源码 |
| S2 | 功能用例生成，使用已移植的 MeterSphere Markdown 定界符与 MdUtil |
| S3 | 接口映射、断言/提取及场景链，校验变量依赖与顺序 |
| S4 | DDL/源码约束的 SQL 候选、表列/别名校验与只读 EXPLAIN；缺数据源时可见阻塞 |
| S5 | 固定前端线索与实际页面证据约束的 UI 步骤；缺页面/来源配置时可恢复 |
| S6 | 生成计划并真实运行；失败归档、诊断和缺陷发生记录 |

阶段、批次、来源版本、生成会话与关联 ID 持久化。重试复用已提交批次和已执行的运行，不重复对外调用业务接口；提交后来源变更会停止旧流水线恢复，后续修改通过显式全局反馈完成。补充缺失环境后可恢复阻塞阶段。阶段缺口不能由无证据 SQL、猜测定位器或虚构测试结果填满。

## 三个执行引擎

HTTP 引擎覆盖 JSON、form、multipart、断言与提取；请求体/响应体截止时间和取消向底层连接传递。变量在运行及每个 DDT 行隔离。鉴权缓存按环境、头部和 Cookie 身份区分，并发刷新采取单次刷新协调，失败记录不会永久占用缓存。

SQL 引擎使用按数据源配置的动态 HikariCP、预编译参数和 JSqlParser 策略。写操作默认不提交，提交、影响行数上限、事务和超时必须明确；无条件或不支持的语法被拒绝。源码绑定查询还必须符合固定 DDL、允许表列和证据范围。数据库操作结果不以重复执行来猜测失败原因。

浏览器引擎使用官方 Playwright for Java。每个运行的上下文、页面、frame/popup、上传、下载、截图和 trace 独立，工作进程受并发与执行期限约束。主进程取消/关闭会回收所属进程树；工作进程监护器验证主进程 PID 和启动时间，主进程被强杀后自行退出并回收浏览器。正常退出关闭 Playwright 对象。Windows 主应用自己的控制台宿主不属于浏览器泄漏。

录制导入解析受支持的 Codegen 动作，未知动作提供错误；导出 Java 可在独立目录使用官方 Playwright 依赖编译运行。AI 输出不作为任意 Java 代码在服务进程内执行。

## 运行、诊断与持续测试

提交执行时冻结资产、名称、环境、数据集、源码与生成证据。执行中编辑只影响下一次运行；报告、失败截图、历史 SQL 和代码定位来自该次快照。混合计划支持自动与人工项，人工结论同样有版本保护。

缺陷按失败身份归并，重复出现追加不可变发生记录，并保留人工状态与删除决策。代码 RCA 锚定发生时的源码快照，核验路径、行号、代码片段与补丁范围。根因和修复建议、人工评价分开保存；补丁不会自动写入业务仓库。

测试计划排期与晨报使用持久化触发游标和幂等键，处理时区、错过触发和重叠策略。晨报的统计事实冻结，对其局部反馈不能改变历史统计。EvalOps 使用真实模型 usage、价格与人工评价，未知用量或费用保持未知。

群通知支持钉钉、企业微信和飞书。只有配置启用的目标才投递；失败回执允许有限重试，POST 后未收到确认等结果记为 `UNCERTAIN`，不自动重复发送。人工确认重试保留同一 delivery ID；接收端不支持幂等时，不宣称严格恰好一次。实现验收使用本地接收端，没有发送真实群消息。

## 故障、导入与发行

MySQL 是任务和应用事实的唯一持久化来源。队列任务在重启后恢复领取；进行中的过期租约任务标为中断，含潜在外部写入的运行不自动重放。租约维护先按主键 `SKIP LOCKED` 再在独立短事务中重检状态，已过期租约不续活。

SSE 通过一条 SQL 读取任务状态、项目可见性及最多 1,000 条后续事件，状态和事件使用同一查询快照。事件事务提交后唤醒进程内订阅者，空闲时每秒补读数据库以覆盖漏通知和其他进程写入；连续事件按 100 ms 的最小查询间隔合并唤醒，满页历史事件直接继续读取。唤醒器只保存通知版本与活跃订阅，不保存业务状态；断开或会话失效后释放订阅。`Last-Event-ID` 仍以 MySQL 持久序号重放。

工作台近期缺陷按批加载元数据和领域内容，近期运行以两次分组查询汇总整页，保留跨状态的用例去重和 DDT 行统计。统计查询直接读取当前数据库，不引入结果缓存。V24 为近期资产排序及同类同父资产位置查询增加联合索引。

导入先预览完整数据和问题，再原子应用。便携导出脱敏、移除服务端来源签章、解除项目专属源码绑定，并将原证据归档为待重新绑定的上下文；通知和排期导入后需显式启用。原项目及运行事实保持不变。

通用导入在持有项目锁的同一事务内完成当前状态预检、分配 ID 和位置，以及字段、父级、引用与领域策略校验。公共资产按依赖顺序写入，领域行按类型分组，以每批 250 行的 JDBC batch 写入；关系、加密修订、审计及 observer 副作用同事务提交，最后保存导入回执。位置和引用的临时复用范围仅限这次事务，不能替代编辑或 AI 采纳时的版本检查。平台 MySQL 连接启用 `rewriteBatchedStatements`，不改变事务提交边界、业务数据源连接池或数据库持久性配置。

预检通过 `CreationValidation` 在单次调用内复用项目存在性与引用类型查找，保留逐节点字段和领域策略校验。预览结果不持有该对象；应用导入时重新创建校验范围，已删除或跨项目的引用仍会拒绝整批提交。

发行 JAR 内嵌前端；只转发八个已知页面路由，未知 API 与缺失静态文件仍返回 404。启动器使用实例配置和受管进程身份，敏感值只经子进程环境传递；优雅停止入口默认关闭，只接受本机连接及实例随机令牌。一致备份先停止自有应用，再复制数据库、受管文件与有效密钥。恢复校验后仅写入空目标，未完成的恢复留下标记并阻止启动。操作命令与失败处理见 [operations.md](operations.md)。
