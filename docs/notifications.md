# 群通知

在「项目管理 → 项目资源 → 群通知」创建普通资产，选择钉钉、企业微信或飞书，填写机器人地址并由人工启用。默认关闭、仅失败通知、最多自动重试 3 次、单次发送期限 10 秒。通知资产沿用手工编辑、排序、版本历史、AI 草稿、模板和导入导出；AI 不能打开启用开关。URL 和密钥通过现有资产加密与脱敏机制保存。

钉钉使用 Markdown，可选签名密钥；企业微信使用 Markdown，认证 key 包含在机器人 URL 中，不接受单独的签名密钥；飞书使用交互卡片，可选签名密钥。已启用配置必须提供有效 HTTP/HTTPS 地址，禁止地址中的用户名/密码、片段和非法端口。允许受控本地接收端进行测试。

## 完成事件与固定报告

正常运行在自动项和人工项全部结束后产生一个完成事件。取消、中断等强制终态也记录事件。事件包含运行 ID、项目和计划名称、状态、完成时间及实际计数；不包含请求头、变量、错误响应正文或机器人凭据。

同一运行最多一个完成事件。后来修改人工执行结果、资产、项目名称或源文件，不改写已记录的通知报告，也不为同一次运行重新发消息。报告中的原始统计与当前运行详情可能因此不同，两者都有独立记录。

订阅启用与事件产生按项目串行化，使用递增事件序号确定边界。首次启用、停用后再启用都从当前序号开始，不补发停用期间的运行。持续启用时修改配置保留游标，新事件使用新配置；已排队任务和自动重试必须仍匹配原配置版本。编辑名称、确认状态和重排也会改变资产版本，因此同样阻止旧排队任务。已经开始发送的请求会继续留下实际结果审计。

「仅失败通知」包含失败、阻塞、错误、取消和中断。符合全量条件但被此选项跳过的运行保留 `SKIPPED_CONDITION` 记录，未启用期间不生成投递记录。

## 投递、重试与未知状态

每个「通知资产 + 完成事件」只创建一条投递记录，每次尝试都有任务 ID、来源、配置版本、开始/结束时间及结果。每次尝试的目标配置单独加密，公共历史不返回它。固定报告在所有尝试中复用；`X-AITest-Delivery-Id` 保持一致，可供自建接收端实现去重。

HTTP 2xx 仍需平台明确成功码：钉钉/企微 `errcode=0`，飞书 `code=0` 或兼容 `StatusCode=0`。飞书两个字段冲突、无有效确认、非法响应、响应超过 16 KiB、发送期间取消或中断等情况记录 `UNCERTAIN`。未知送达状态不会自动重放。

明确的 HTTP 408、429、5xx，以及连接尚未建立的错误，按指数间隔有界重试。其他 HTTP 或平台明确拒绝记录失败，等待人工处理。自动重试上限为 0–5 次，初次发送之外单独计数，并固定在该投递创建时；人工重试不会重置此预算。单次连接和完整响应使用同一总期限，范围 1–60 秒；不跟随重定向，不关闭 TLS 校验。

人工重试使用界面显示的当前配置版本与原固定报告。版本变化返回冲突，可读取最新通知配置后重新核对。对于 `UNCERTAIN`，必须先检查群消息并勾选接受可能重复发送。接收平台没有幂等保证时，系统不能保证外部消息严格只送达一次。

浏览器在请求前保存本次重试标识及提交时的版本。网络断开或刷新页面后，可点击「确认上次重试结果」，以同一请求取得原任务，不再次派发。相同幂等键配合不同版本或确认条件会被拒绝。已送达或正在执行的记录不能再次新建重试。

任务进程消失后，租约恢复会把已开始但未确认的发送标记为未知；尚未发送的取消/中断保留对应状态。新的进程或并发扫描不会自动重放未知请求。停用、删除通知或删除项目会阻止未开始的发送；已经开始的发送在项目删除后仍保存内部审计，公共接口继续拒绝访问已删除项目。

## 接口与运行配置

| 接口 | 功能 |
|---|---|
| `GET /api/projects/{projectId}/webhooks/{webhookId}/deliveries?offset=0&limit=20` | 固定报告、发送状态、尝试历史和服务发送开关；limit 1–100 |
| `POST /api/projects/{projectId}/webhooks/{webhookId}/deliveries/{id}/retry` | `{baseVersion,idempotencyKey,acknowledgeUncertain}`，返回固定的投递/尝试/任务 ID |

`aitest.notifications.enabled` 默认 true，控制服务是否派发/开始发送；每个资产仍需人工启用。`aitest.notifications.poll-interval-ms` 默认 1000，`retry-delay-seconds` 默认 30。更改服务开关需要重启。发送关闭期间停止消费订阅游标；恢复服务时继续处理已经启用的订阅期间产生的事件。若不希望补发此期间的事件，应停用对应资产后再启用。

V22 创建完成事件、订阅、投递和尝试表。升级不会合成旧运行的完成事件，也不修改已有通知资产内容。备份恢复必须同时包含数据库和本地存储主密钥，否则无法解密尝试配置。历史和事件包含业务名称，应按项目数据保留策略管理。

验证使用真实本地 HTTP 接收端、MySQL 和浏览器。未向真实企业群发送测试消息；本地签名和协议验证不代表企业机器人侧配置已验收。
