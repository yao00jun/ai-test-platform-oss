# 源码变更与定向回归

在项目的源码分析历史中选择一个已完成快照，展开“源码变更与定向回归”。可使用该 Git 快照采集时保存的 baseline，或选择同项目的另一份后端快照。分析使用数据库内保存的文件字节，不读取当前业务工作目录；后来修改源码不改变历史报告。

分析是独立后台任务。页面展示真实 diff 区间、改动方法、调用路径、受影响接口/Mapper 表、解析诊断和完整调用图。方法身份由文件路径、完全限定类名及签名组成，构造器使用独立的 `<init>` 身份。新增使用新图，删除使用旧图；重命名仅在同类、同参数/返回类型且函数体唯一匹配时识别，其他情况分别显示新增/删除。类或文件级声明变更单独标记。

调用解析覆盖已捕获声明中的接收者类型、继承/接口、重载、构造器与潜在方法引用。多个可能实现全部保留；循环调用不会无限遍历。反射、运行时注入、链式动态返回类型和库外调用可能无法解析，界面保留这些缺口。静态调用图不等同于完整运行时覆盖，回归范围仍需人工判断。

候选测试依据真实 HTTP 方法/路径映射 API 定义和用例，再遍历已有场景及计划项引用。不会按固定数量截断。勾选需要的候选，输入名称并创建普通测试计划，随后可通过已有计划详情编辑、调优和执行。空选集不能创建计划；此操作本身不执行测试。引用已有计划项时保留其执行方式、变量、数据集和环境。

创建时重新核对选中资产、依赖版本及子项成员关系。期间的人工修改、删除或新增步骤会触发冲突，历史报告不会覆盖当前资产。重新分析后再选择；重复提交同一原始请求返回同一计划，改变请求必须使用新幂等键。

影响分析与计划创建都保存尚未确认提交的请求身份。丢失响应或刷新页面后可恢复原提交；切换项目或快照后，晚到响应只属于原先的输入。恢复操作不会把未确认请求改造成另一次生成。

计划数据保存 `sourceSnapshotId/impactId`，运行时这些固定证据随执行快照一起保存。它们指向不可变证据仓库，不参与可编辑资产的引用拓扑；跨项目、未完成或不匹配的来源会被拒绝。已有无源码绑定的历史运行仍可读取。

旧版源码快照保持原有文件和解析结果；新影响分析必要时用当前解析器重新读取其固定字节，并保存升级产生的诊断。快照本身不被改写。

资源边界：单次最多 60,000 个方法、200,000 个调用、250,000 条候选边；Git diff 输出上限 32 MiB、超时 45 秒。超过上限显示失败并要求缩小范围，不输出貌似完整的截断报告。Git 比较在独立临时目录中运行，禁用外部 diff/textconv，不执行被分析项目。
