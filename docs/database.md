# 数据库初始化、迁移与恢复

平台库要求 MySQL 8.4 LTS、InnoDB、utf8mb4。当前本地验收使用 MySQL 8.4.10；未以 H2 替代 SQL、锁、事务和恢复验收。业务 SQL 数据源与平台库分开配置，不将两种连接池混为一体。

## 初始化与升级

创建一个空数据库及只能访问该库的应用账号，在实例 `config.json` 中填写 JDBC 地址、用户名与密码，然后启动应用。Flyway 按序应用 `database/migration/` 中的迁移，并保存校验和。

应用启用了 `validate-on-migrate`，关闭 `baseline-on-migrate` 和 `clean`。当前结构版本为 V24；既有 V1–V23 的内容保持不变，V24 已在本轮真实 MySQL 测试库验证。后续变化必须增加新迁移，不能编辑已应用迁移规避校验错误。每次升级先作完整备份。数据库校验失败时应用不就绪，应使用匹配源码及迁移排查，不能清空运行库解决。

`docs/db-schema.sql` 是按当前迁移顺序汇总的结构审阅副本，不创建 Flyway 历史。初始化入口始终是应用迁移；不要同时手工执行该副本。实施前的 SQL 草案在 源码仓库的设计归档 保留，仅供历史对照。

| 迁移 | 主要内容 |
| --- | --- |
| V1–V2 | 项目、版本化公共资产、修订及领域表 |
| V3–V5 | 任务/事件、AI 会话、受管文件、导入与变更集应用 |
| V6–V10 | 执行选项、不可变运行/步骤、浏览器选项、交换元数据与精确定位 |
| V11–V15 | 缺陷发生、流水线批次、文档提交、接口 Diff、计划排期 |
| V16–V19 | 固定源码、影响范围、生成证据、RCA 与人工评价 |
| V20–V22 | 模型调用用量、持久化晨报、通知事件/投递/尝试 |
| V23 | AI 消息按 job_id、role、status 建联合索引，隔离草稿采纳/拒绝的消息更新 |
| V24 | 近期资产按更新时间/ID 排序、同类同父资产位置查询的联合索引 |

业务资产修改包含公共记录、类型记录与修订，均在同一事务内写入。AI 生成与外部网络调用不在这些短事务内进行。变更集以完整选择集检验 CAS 和依赖后原子应用。

通用导入以 250 行为 JDBC 分批单位，整批导入仍只有一个资产提交事务；任意批次、修订、关系或 observer 失败都回滚全部资产和导入回执。平台连接启用 MySQL JDBC 批量语句重写，不省略修订/审计，不改变 `innodb_flush_log_at_trx_commit`、`sync_binlog` 或业务数据源配置。

## 本地开发数据库

`scripts/aitest.ps1 mysql`（Linux：`scripts/aitest.sh mysql`）可使用已安装的 MySQL 8.4，或下载官方 8.4 发行文件。它只管理本项目的 `.runtime/mysql` 数据目录，默认监听 127.0.0.1:3307，并生成开发、集成和业务测试库及随机账号口令。不要把运行数据提交到 Git。

```powershell
.\scripts\aitest.ps1 mysql
# 或指定已安装客户端/服务端目录
.\scripts\aitest.ps1 mysql -MySqlHome 'E:\Tools\mysql-8.4.10-winx64'
```

普通集成测试使用专用 `ai_test_platform_test` 与 `ai_test_business_test`。进程恢复和容量验收在本地 bootstrap 实例上创建随机 `ai_test_acceptance_<id>` 库，并只删除本次测试自己创建的库。不要为测试提供业务数据库。进程测试的外部 `AI_TEST_PROCESS_DB_URL` 分支只能供单个测试指定空库，重复运行整套测试应使用自动创建的独立库。

## 备份与恢复

完整备份同时保存 MySQL 数据、受管文档/附件、源码快照和实际生效的 32 字节主密钥。加密模型配置、数据库口令、运行历史和人工评价通过完整备份保留。单独导出资产不包含完整历史，也不能作为灾难恢复包。

使用 [运行手册](operations.md) 中的 `aitest.ps1 backup` 与 `aitest.ps1 restore`（Linux 为 `aitest.sh`）。恢复目标必须是已有的空数据库和空存储目录，脚本保留目标数据库连接、端口与路径配置，将原配置另存参考。数据导入失败可能留下部分 DDL；脚本不会自动删除这些表，而是留下恢复标记阻止启动，下一次使用新的空目标重试。
