# 固定源码诊断与人工评价

失败诊断读取本次运行绑定的不可变源码快照，以实际失败结果中的 Java 堆栈定位代码。执行后修改业务目录，不会改变历史诊断依据。普通缺陷、旧诊断和没有源码的项目仍可使用手工编辑与 AI 文字诊断。

## 使用流程

1. 在项目采集后端源码，给用例、场景或计划绑定固定快照，再执行测试。
2. 对实际失败运行发起诊断，或由已启用的计划自动诊断。缺陷的「发生记录」保留每次原始现场；同指纹再次失败只追加发生记录，保留人工修改、关闭状态和已删除记录。
3. 打开缺陷「源码诊断」，查看捕获时的文件、行窗口、文件哈希与固定基线差异。类名、文件名、方法和行范围共同参与匹配，支持 Java 模块和类加载器前缀。未命中、越界、多份匹配和非 Java 堆栈均给出具体缺口。
4. 手工修改代码根因、关联位置、补丁或置信度，并保存。草稿切换标签或刷新后保留原版本；并发编辑返回冲突，需核对后显式合入最新内容。
5. 点击「🪄 局部 AI 调优代码诊断」，连续输入反馈。请求限定 `targetFields=["codeDiagnosis"]`，成功后只原地替换当前缺陷的结构化诊断；其他人工根因、修复建议、状态、兄弟缺陷和引用保持不变。可以在版本历史中恢复旧版本。
6. 补丁供人工审阅，可复制或下载 `.patch`。平台不会把建议写入业务仓库。下载保留文本字节；Windows 剪贴板可能把换行转换为 CRLF。
7. 在独立「人工评价」区记录正确、部分正确、错误或未评价，并单独确认是否为退化缺陷。AI 的置信度和退化推测不会被当成人工判断。

## 数据与校验

`BUG.data.codeDiagnosis` 默认为 `{}`。非空值使用版本化对象：

```json
{
  "formatVersion": "aitest.code-rca/v1",
  "root_cause": "依据保存的堆栈提出的待验证假设",
  "affected_code_path": "src/main/java/shop/OrderService.java:142",
  "suggested_fix": "",
  "is_regression": null,
  "confidence": null
}
```

位置和补丁均可为空。置信度只能为有限的 0–1 数值或 null；退化推测只能为 boolean 或 null。类型和结构校验覆盖普通 CRUD 与交换。AI 生成、局部调优、全局预览及已保存变更集的采纳，还需验证该缺陷原始发生记录里的固定源码依据。

AI 补丁使用统一差异格式，文件头必须是捕获的相对路径，修改区间和上下文必须与保存窗口匹配。新增、删除、重命名、二进制、文件模式变更和越界路径不被自动接纳。源码和补丁只按文本显示，HTML 不执行。来源证据由服务器保存，模型不能提交自己的源码证据或人工评价。

读取最多 8 份失败关联快照、前 12 条 Java 文件行号堆栈，每个匹配位置取前后 6 行，总源码与基线差异限制为 80,000 字符；省略和读取失败有可见诊断。代码诊断补丁上限 100,000 字符、2,000 行。源码显示和提示词片段沿用快照脱敏。命中堆栈说明存在定位依据，仍需要核实根因和修复建议。

人工评价保存在 `bug_rca_evaluation`，与可编辑资产分离。每条记录保存被评价资产版本及 `rootCauseAnalysis/suggestion/codeDiagnosis` 的规范化内容摘要；诊断变化后，旧评价留在历史，当前显示未评价。仅变更严重度等非诊断字段不会自动使原判断失效。选择「未评价」会追加一条清除当前判断的记录。

评价写入使用项目隔离、资产版本检查和幂等键。同键同输入恢复原记录，同键不同输入返回冲突；网络响应丢失后，页面重试同一提交身份。操作者和来源由服务器写为 `LOCAL_USER/MANUAL`。这是当前本地工作台的操作者身份，不代表已经接入企业人员认证。

## 接口

- `GET /api/projects/{projectId}/bugs/{bugId}/code-evidence`：原始发生记录的固定源码依据；人工或历史缺陷返回带说明的空证据。
- `GET .../rca-evaluations?offset=0&limit=25`：`{current,items,total,diagnosisHash}`，current 仅对应当前诊断摘要。
- `POST .../rca-evaluations`：`{baseVersion,verdict,regression,note,idempotencyKey}`，返回保存的独立评价。
- `verdict`：`CORRECT/PARTIAL/INCORRECT/UNREVIEWED`；`regression`：`CONFIRMED/NOT_REGRESSION/UNREVIEWED`。

迁移为 V19。历史诊断的七项文字协议保持兼容，新输出可增加第八项 `codeDiagnosis`。模型故障、无效输出和取消保留失败历史，不把测试执行状态改为通过。
