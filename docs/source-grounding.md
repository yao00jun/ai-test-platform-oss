# 固定来源生成与多轮反馈

五类输入包括 PRD、API 文档、后端源码、前端源码和 DDL。源码/DDL 在项目中单独采集，或由工作台的“新建全自动测试”准备；生成只引用 READY/PARTIAL 的固定快照。只提供 PRD/API 的既有流程继续可用。PARTIAL 的解析诊断和上下文省略数量会进入生成上下文。

## 提交与恢复

流水线、通用 AI 生成及全局反馈可指定 `sourceSnapshotId`。流水线首次绑定后，恢复与反馈继续使用同一 ID。界面输入源码路径时先提交分析；准备阶段分别冻结分析请求与流水线请求的幂等身份。响应丢失、刷新及项目切换后的晚到响应均不重新创建分析或资产。

通用生成可选择同项目快照。全局反馈的现有资产保留各自来源；新增资产首先继承父资产来源，再使用本轮指定来源。没有指定且当前范围只有一个来源时自动继承；有多个来源的新根资产需要明确选择。普通修改可同时涉及多个来源，并分别校验，不能把目标重新绑定到另一个快照。界面保留会话最后一次明确选择的快照，未收到确认的请求重试复用相同选择与幂等键。

## 生成依据与执行

S1/S2 对照 PRD、DTO 参数校验及实际业务分支。S3 使用接口与静态调用事实。源码不会证明模型理解正确，也不替代实际模型质量评估。

S4 通过 SQL AST 校验表、别名、列、联表、CTE、参数和返回绑定。仅有 DDL 可以保存普通 SQL 资产，但未绑定数据源时，执行提交会在任何兄弟 HTTP/SQL/UI 副作用前拒绝，并返回 `DATABASE_SOURCE_REQUIRED`。人工绑定真实数据源后可执行。有数据源时生成和调优在资产事务外完成真实 Schema/EXPLAIN 验证；采纳检查绑定版本和已验证查询的摘要。

S5 优先已观察页面与已有录制，其次使用静态 Vue/React 定位事实。每个 selector、拖放目标、Frame 和导航地址都检查来源。静态/条件定位明确显示待运行验证，缺实际地址时保存无虚构导航的草稿。运行地址缺失返回 `WEB_BASE_URL_REQUIRED`。

`generationEvidence` 是只读元数据，包含固定清单哈希、表列/定位来源、配置缺口和服务器认证的证据摘要。模型自称观察到某个元素不会获得运行时证据权限；候选采纳会再次验证。元数据不参与变量依赖扫描或执行插值，也不会因包含 `${token}` 等源文件字面量而造成假依赖。运行依然保存完整的不可变资产与来源快照。

## 人工编辑和局部优化

双击、手工 CRUD、排序、导入导出和历史恢复继续使用现有资产服务。SQL 或 UI 步骤仍有独立 ID。局部调优使用当前人工内容、目标版本及固定来源，只替换允许字段；并发人工保存赢得 CAS 后，迟到候选记录冲突。全局候选必须显式选择采纳，整个选择原子提交。证据失败不自动改变兄弟记录或已运行的快照。

提示词落地协议位于后端 `asset_generation.st`、`pipeline_stage_contract.st`、`pipeline_feedback.st` 和 `local_refinement.st`；它们补充业务模板，不能扩大本次目标范围。真实公司模型接入后的质量验收与本地 HTTP 协议 fixture 验证分别记录。
