# AI 效能与模型计价

工作台的“AI 效能评估”读取当前项目的实际调用、任务、运行快照和人工诊断评价。可切换全部记录或最近 1 / 7 / 30 天；接口也接受 `from`、`to` ISO 时间，采用 `[from, to)` 区间。调用时间以开始调用为准，运行以创建时间为准；评价取截止时间前每个诊断摘要的最新人工判断，再筛选判断时间。

| 指标 | 计算口径 |
| --- | --- |
| 模型调用 | 每次逻辑网关调用一条。初次生成和格式修复分别计入。一次调用可包含有界限流/兼容尝试；HTTP 尝试数单列。正常收到正文也可能在后续 JSON、证据、资产或版本校验中失败。 |
| 生成有效率 | 至少发起过已采集模型调用的任务，`SUCCEEDED / (SUCCEEDED + FAILED)`。流水线明确 `BLOCKED` 的控制任务单列；取消、中断和进行中不进入分母。有效含完成验证的预览，不等于人工采纳或业务测试通过。 |
| AI 资产执行通过率 | 运行快照中来源为 AI 的运行项，`PASSED / (PASSED + FAILED + ERROR)`。DDT 每行一项，人工完成的执行项也可进入。阻塞、跳过、取消、中断、待人工单列。修改现有资产不回写旧运行依据。 |
| RCA 正确率 | 每个 `(缺陷 ID, 诊断摘要)` 的最新人工评价，`正确 / (正确 + 部分正确 + 错误)`。撤回为“未评价”后退出分母。原有诊断版本的历史评价仍保留。模型 confidence 不参与计算。 |
| 退化缺陷 | 每个缺陷截止时刻的最新人工确认，按缺陷去重。平台没有全部退化缺陷的真实基数，因此不虚构拦截率。 |
| Token | 原始 JSON 或 SSE 中供应商实际返回的 `usage.prompt_tokens/completion_tokens/total_tokens`。保留最后一份累计报告，不累加重复 SSE 元数据。没有报告为 `null`，明确报告为零才是 0。汇总同时显示报告覆盖次数。 |
| 费用估算 | `输入 Token × 输入单价 / 1000000 + 输出 Token × 输出单价 / 1000000`。必须同时具备已启用价目和输入、输出用量。无资料保持 null，各货币分开汇总。 |

“查看调用记录”提供分页明细，可按请求的模型名称及配置版本筛选。请求模型、响应模型分别保存；使用别名或供应商路由时二者可能不同。按模型的生成计数表示该版本参与的任务，同一任务切换模型时可能出现在多个组，不能直接相加。执行与人工评价保留项目范围口径，不凭调用时间猜测某个模型版本的贡献。

价目在“模型设置 → 模型计价”维护。每次保存需要当前版本，陈旧保存返回 409；可以重新载入后修改。价目以请求模型名称匹配，模型别名需要独立配置。新价目只影响后续调用，已有调用保存当时的价目版本、货币、输入/输出单价和估算结果，不会重新计价。缓存折扣、供应商阶梯和附加收费不在该基础估算内，以实际账单为准。

调用记录不保存 API Key、base URL、提示词或生成正文。正文和候选仍由既有 AI 会话审计保存。记录开始与结束不依赖资产采纳事务成功；进程中断留下的进行中记录，读到终止任务时显示中断，不能伪造完成耗时或用量。

Spring AI 2.0 的流聚合器会合成零用量，因此采集器在 SDK 归一化前有界读取原始响应，且不改变交付给 SDK 的字节。兼容层只请求标准 `include_usage`，只有网关明确拒绝该选项、且没有收到正文或真实用量时才移除 `stream_options` 后重试。已经产生正文、无关模型错误和认证错误均不重放。

接口：

- `GET /api/projects/{projectId}/evalops?from=...&to=...`
- `GET /api/projects/{projectId}/evalops/invocations?offset=0&limit=25&modelName=...&modelVersion=...&from=...&to=...`
- `GET /api/settings/model/pricing?modelName=...`
- `PUT /api/settings/model/pricing`：`modelName/baseVersion/enabled/currency/inputPerMillion/outputPerMillion`。

统计只覆盖新增采集器启用后的模型调用；历史运行和人工评价可按现有不可变证据计算。公司模型凭据尚未提供，本地协议验证不能证明公司模型生成质量。
