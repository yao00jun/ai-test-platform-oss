# 自动质量晨报

在工作台展开“晨报设置”，填写每天的当地时间、IANA 时区、生成要求和自动重试上限，再由人工勾选“启用每日晨报”并保存。默认关闭；AI 生成、导入和局部调优均不能启用排期。手工质量简报、全局反馈和局部正文调优继续独立使用。

设置采用版本比较保存。另一位编辑者先保存时，当前草稿保留；“读取最新设置并保留我的修改”只把本地改过的字段放到最新版本上，其余字段采用服务器的新值。检查后再次保存。取消勾选会阻止新的自动派发和自动重试；已经派发的任务可以使用固定快照完成。

## 时间与事实范围

- 每项目、每个当地日期最多一条发生记录，数据库唯一约束与项目锁共同保证并发去重。修改时区后，同一日期也不重复生成。
- 每次修改设置后的下一次触发严格晚于保存时间。长期停机只合并到最近应触发的日期，历史显示 `missedFrom`，不产生逐日积压。
- 夏令时跳过的时刻按该时区的时钟缺口顺延；重复时刻采用较早的偏移，当天只触发一次。
- 晨报覆盖 `[前一当地日期的起点, 当前当地日期的起点)`，夏令时变化日可以为 23 或 25 小时。范围选择的是在该区间内**创建的运行**，运行状态以首次统计捕获时的真实记录为准。
- 统计捕获后先持久化，再调用模型。重试复用同一统计、哈希、日期、时区、生成要求和原重试上限。后来修改排期、运行结果或用例不会改写该次统计。
- 无运行样本时通过率为空。正文是待人工核验的分析，不是自动发布许可。AI 只能新增一条非空 `QUALITY_BRIEF`，不能改写统计或其他资产。

简报、变更集采纳、成功会话记录、发生记录的资产引用和成功任务状态在同一事务中提交。无效输出、模型失败或取消不会留下空简报。项目删除后不再派发或发布晚到的生成结果。

## 失败、重试与历史

历史展示日期、时区、状态、每次尝试的任务 ID、错误和固定统计。限流、连接问题和输出格式错误可按原配置自动重试 0–3 次，默认间隔 60 秒，后续按 2 倍增长；认证未通过或未配置模型需要处理配置。取消或中断不会自动重放。自动重试预算属于一次发生记录，手工重试不会重置它。

失败、取消、中断或等待自动重试时，可点击“手工重试此晨报”。已成功或正在执行的记录不会重复创建资产。网络丢失确认时，浏览器保存重试标识；重载后点击“确认上次重试结果”会提交同一标识，取回原任务。

“查看生成的简报”打开普通资产详情，可以手工编辑、查看历史、导出，或多轮 AI 调优正文。事实快照由服务器保护，调优只改变允许的目标字段；其他简报和资产不受影响。

## API 与运行配置

| 接口 | 行为 |
| --- | --- |
| `GET /api/projects/{projectId}/morning-brief/schedule` | 返回配置；未配置时 `version="0"`、`enabled=false`、`nextFireAt=null` |
| `PUT .../schedule` | 接受 `baseVersion/enabled/time/timezone/instruction/maxRetries`；拒绝未知字段、非法类型，旧版本返回 409 |
| `GET .../history?offset=0&limit=20` | 返回 `{items,total}`；`limit` 为 1–100，各项含 `attempts` 与固定 `metrics` |
| `POST .../occurrences/{id}/retry` | 输入 `{idempotencyKey}`，202 返回 `{occurrenceId,jobId}`；同键取回原尝试，新键但状态不允许时返回 409 |

`time` 必须为 `HH:mm`，`timezone` 必须是 IANA 标识（如 `Asia/Shanghai`、`UTC`），`instruction` 为 1–16000 字符，`maxRetries` 为 0–3 的整数。所有读写按项目隔离。

服务配置 `aitest.morning-brief.enabled=false` 可关闭本服务的自动扫描，页面会提示；每个项目的启用选择仍保存。`poll-interval-ms` 默认 1000，`retry-delay-seconds` 默认 60。任务由既有持久化 JobService 派发，不增加队列中间件。

Flyway V21 新增 `morning_brief_schedule`、`morning_brief_occurrence`、`morning_brief_attempt`。备份必须同时包含这些表及资产、修订、AI 会话、任务和本地附件。
